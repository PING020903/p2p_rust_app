# 跨局域网联通（Cross-LAN Connectivity）方案

> 目标：让 `p2p_rust_app` 在两个不同局域网（不同城市、不同 NAT 之后）的节点之间也能通讯。
> 本文档聚焦"**打洞不可行**"这一中国境内家庭宽带的普遍现实，承接 `docs/NAT_TRAVERSAL_PLAN.md`。
>
> 现状（0.21.0）：**TCP + Noise + Yamux** 传输、**mDNS 局域网发现**（advertise/stealth/off）、
> 文件传输（0.19.0）。**IPv6 全局直连地址互拨已实现**（0.19.0 UX：启动打印 + `/listen` 重打，
> 对方 `/dial /ip6/...` 即连，需路由器放行端口），但**跨城市真实双端实测待验证**；
> 跨城市 **relay/会合房间仍未实现**。
> relay 打通后，L2/L3（身份/信任/会话/群/文件）**零改动**——三层架构红利。

---

## 〇、部署现实：中国境内家庭宽带（先认清事实）

> 部署对象是国内不同城市的两台家庭宽带设备。这套网络现实**决定了方案骨架**：

| 事实 | 含义 |
|---|---|
| **IPv4 全是大内网（CGNAT）** | 家庭宽带 WAN 拿的是 `100.64.x.x` 私网地址，公网 IPv4 只有申请才可能有且逐年收窄 → **IPv4 打洞无望** |
| **PPPoE + 光猫账号认证** | 出站流量需账号验证放行；**每日凌晨强制重拨断网几分钟**（IP/租约变更）→ 所有 WAN 长连接周期性失效 |
| **IPv6 普遍下发** | 国内自 2020 年起强制推进 IPv6，家庭宽带基本都有 → **唯一的"非大内网"免中继直连机会**（无 NAT，每设备一个全球地址） |
| **海外公共点不可靠** | 公共 libp2p relay / 海外 MQTT broker 延迟高、易被 QoS → relay 点必须**国内可达** |

**由此确定的策略：IPv6 直连优先（免费、零中继）+ 国内可达 relay 兜底（可靠基线）；IPv4 打洞从路线图跳过。**

---

## 一、核心结论

> **两个私网节点之间，只要打不了洞（IPv4 大内网必然如此），就必然存在一个"双方都只能出站连到的公共可达点"，流量经它转发。**
> 中国场景下：IPv6 是唯一的"无需公共点"路径，其余全部走 relay。

四个关键设计决策：

1. **中继是"星型单跳"，不是链式多跳** —— 跳数是设计写死的 1，不是未知数。
2. **公共点有两个角色，可拆分**：**会合**（发现彼此、交换地址）与**转发**（搬运数据）。能摆脱转发（IPv6 直连），但跨城市通常离不开会合。
3. **选路用"测量"，不用"计算"** —— 互联网内部路由是黑盒；枚举候选路径、测 RTT、取最优，而不是计算拓扑。
4. **连接生命周期自愈** —— 每日重拨断线是常态，L1 必须自动感知、重连、刷新地址，应用无感。

---

## 二、问题拆解：两个独立的问题

跨局域网通讯被经常混为一谈，实为两件事：

| | 问什么 | 需要吗 |
|---|---|---|
| **PeerID 发现**（目标是谁） | 我该跟谁说话 | 基本**不需要做**——PeerID 是全球稳定标识（Ed25519 公钥哈希），不随网络位置变化；联系人/信任关系里已有 |
| **路径发现**（目标此刻在哪） | 这个 PeerID 现在怎么到达 | **需要**——以 PeerID 为 key 的"定位"，与局域网层次无关 |

关键认知：**不存在"逐层局域网搜索 PeerID"**。PeerID 要么你已经知道，要么通过一个**与局域网无关的会合点**一次性获得。中继/IPv6 模型把嵌套任意深的局域网压平成一个可达空间——双方只做出站连接（或 IPv6 全局地址直连），嵌套层数无关紧要。

### PeerID 的三种来路（都不依赖局域网）

1. **已有联系人 / 手动交换**：地址内嵌 PeerID（`/p2p/<peerid>`），直接 `/dial`。
2. **会合房间 / topic**：双方加入同一房间码 → 会合点报出"房间内在线节点 + 各自地址" → 一次性获得 PeerID 与路径（mDNS 的跨 LAN 替代品）。
3. **DHT**（libp2p Kademlia，需 public bootstrap）：`key → peer` 查找；本工程联系人量小，**暂不必要**。

## 三、公共点：双角色与候选形态

### 3.1 两个角色

| 角色 | 干什么 | 能否摆脱 |
|---|---|---|
| **会合 / 信令**（rendezvous） | 让双方发现彼此 + 交换候选地址 | 跨城市**通常还得靠它**（除非手动地址交换 / IPv6 直连已知地址） |
| **数据转发**（relay） | 实际搬运帧 | **可以**——IPv6 直连成功就甩开它 |

### 3.2 候选"公共点"形态（国内可达优先）

| 形态 | 会合 | 转发 | 国内可达 | 自控性 |
|---|---|---|---|---|
| **香港 VPS 自建 relay + 房间服务** | ✅ | ✅ | ✅（~30-50ms，免备案） | 完全自控 ⭐ 首选 |
| **国内 VPS** | ✅ | ✅ | ✅ | 自控，但备案/价格门槛 |
| **公共 MQTT broker（EMQX 等）** | ✅ | ✅ | ⚠️ 视部署地 | 依赖公共服务 |
| **公共 libp2p relay（IPFS 生态）** | ✅ | ✅ | ❌ 海外为主 | 依赖公共服务，不可靠 |

> 注：libp2p 的 `relay client + identify + dcutr` 原生实现了"先经中继建连 → 升级直连 → 中继退位"整套流程。本方案以 **IPv6 直连**为升级目标（而非打洞），relay 用香港 VPS 自建为终态。

## 四、路径模型：候选测速选路（中国场景）

### 4.1 为什么"跳数"不是未知数

| | 谁决定 | 能否控制/计算 |
|---|---|---|
| **IP 层路径**（A→中继、中继→B 经过多少路由器） | BGP / 运营商路由 | **黑盒，不可算也不必算**——保证"能通"，只关心时延，用测的 |
| **应用层中继**（协议套几层转发） | 我们的设计 | **= 1，写死**。绝不链式中继 |

### 4.2 候选路径与优先级（按中国网络现实排序）

```
bootstrap 后，A 已知 B 的候选地址，B 同理。
候选路径（按优先级）：
  P1 host    对方局域网地址        → 同网段直连（mDNS 已覆盖）
  P2 ipv6    对方全局 IPv6         → 免中继直连（双方有 IPv6 + 路由器放行入站端口）
  P3 relay   国内可达中继（兜底）     → 出站必通，可靠基线
  P4 friend  共同在线好友           → 可达性图 BFS 最短（≤3 跳，可选扩展）
  （IPv4 打洞：CGNAT 下无望，跳过）

尝试 + 测 RTT：
  按优先级试；命中可用且最快 → 使用
  P2 失败（无 IPv6 / 防火墙挡）→ 回落 P3 relay
  全失败 → 留在 P3（中继转发数据）
```

要点：
- **连通性是确定的**：P3 出站连接永远能建 → 链路先经中继确认，升级失败不断连。
- **IPv6 直连是机会式的免费升级**：只要双方有全局 IPv6 + 放行端口，就甩开中继；每日重拨后 IPv6 地址变了要重新观测。
- **选路确定**：候选集有界 + 固定测速流程 → 结果因网络而异，但流程确定、可复现。

### 4.3 好友中继（可达性图 BFS）——可选扩展

若要做"通过共同好友转发"（A→C→B）：
- 图 = **自有可达性图**：节点 = 已知 peer，边 = "已证实能直连"（IPv6 直连或公网 IP）。
- **最短公共点 = 图上最短路**（BFS），跳数 = 距离，**确定且有界**（设 `max_hops=3`，超限放弃）。
- 每一跳都是认识、信任、在线的节点做 store-and-forward，不是"未知外部中继"。

## 五、发现层方案（L1）

| 场景 | 机制 | 状态 |
|---|---|---|
| 同局域网 | mDNS（advertise/stealth/off） | ✅ 已有 |
| 跨城市（MVP） | **手动交换地址**：IPv6 地址（已实现打印/`/listen`，**跨城市实测待验证**）或 `/p2p/<relay>/p2p-circuit/p2p/<peerid>`（relay 未做） | 部分已做 |
| 跨城市（进阶） | 会合房间：`/room <码>` 加入 → 自动发现同房间节点 → 拨号 | 待做 |
| 大规模 | DHT（暂不必要） | 不做 |

跨 LAN 只是给现有 `registered: HashMap<PeerId, Vec<Multiaddr>>` **多一种填地址的来源**，L2/L3 无感。

## 六、分阶段实施

### 阶段 0（MVP，零服务器）——手动地址互通
- relay 客户端接入（先用可用公共点试水，终态香港 VPS）。
- 拨号支持 relay 路径：`/p2p/<relay>/p2p-circuit/p2p/<peerid>`。
- **IPv6 探测 + 直连拨号**：启动时探测本机全局 IPv6；`/dial` 支持 `/ip6/...` 地址。
- 目标：跨城市节点经 relay 手动互通（消息/文件全走通）；有 IPv6 时直连。
- 验收：
  1. 两个跨城市节点互贴 relay 地址后 `/chat` 收发消息；
  2. 双方有 IPv6 + 放行端口时，经 IPv6 直连（中继不参与）；
  3. **模拟每日重拨（断外网几分钟）后应用自动恢复**。

### 阶段 1——会合房间
- relay 侧加房间服务（或复用 topic 语义）：`/room <码>` 加入 → 自动发现同房间在线节点 → 自动拨号。
- 目标：输入房间码即互通，不再手贴地址（mDNS 的跨城市等价物）。

### 阶段 2——连接生命周期自愈（应对每日断线）
- relay/直连连接纳入 L1 心跳 + 超时 + 自动重拨。
- 候选地址带 TTL，重连后重新观测（identify / IPv6 前缀刷新），丢弃过期地址。
- 机会式升级**周期重试**：IPv6 直连失效后回落 relay，周期性再试。
- 文件传输遇断线：**中止 + 提示**（断点续传留后续）。
- 目标：每日重拨断网期间应用无感自愈，不丢会话状态（PeerID 稳定 → 恢复后自动重连进既有会话）。

### 阶段 3——优化
- NAT/网络环境探测 + 启动提示（"IPv6 直连可用 / 仅走中继"）。
- 候选集测速选优（§4.2）落地；relay 带宽/时延观察。
- 香港 VPS 自建 relay + 房间服务上线，摆脱公共点依赖。

## 七、对工程的影响（改动清单，按阶段）

| 模块 | 改动 |
|---|---|
| `Cargo.toml` | 加 feature：`relay`、`identify`（阶段 0）；`upnp` 可选；`dcutr` **跳过**（无打洞场景） |
| **L1 `node.rs`**（最大改动） | transport 支持 relay 拨号与 IPv6 地址；`NodeBehaviour` 加 `relay client` / `identify`；候选路径表 + 测速选路；**连接生命周期管理**（重拨 / 候选 TTL / 升级重试） |
| **L1 发现层** | 保留 mDNS；新增"手动 relay/IPv6 地址"（阶段 0）与"会合房间"（阶段 1）地址来源；IPv6 探测 |
| **配置/命令** | 新增：relay 地址配置、`/room <码>`（阶段 1）；启动打印 IPv6/中继可用性 |
| **文件传输** | 断线时中止 + 提示（阶段 2） |
| **L2/L3** | **几乎不变**——连接一旦建立，心跳/消息/群/文件全部照旧 |

## 八、风险与取舍

1. **IPv6 直连依赖用户环境**：路由器入站防火墙默认挡，需一次性放行端口（"配置"非"打洞"）；部分光猫/用户未开 IPv6 → 只能走 relay。
2. **relay 依赖第三方/自建**：公共点不可控（海外不可靠）→ 终态香港 VPS 自建；中继挂了，跨城市互通即断。
3. **端到端加密语义**：经 relay 转发的是 **Noise 加密**流量，中继只见密文（libp2p relay 天然满足）。
4. **每日断线期间**：长文件传输会中断（阶段 2 先中止提示，续传后续）；会话状态不丢（PeerID 稳定）。
5. **libp2p 0.56 relay/identify API 有版本变动**，实现时按文档核对。
